# Codex Plugins: Почему узкое место переместилось в Workflow

## Тезис

Модель (GPT-5.5 / Codex) стала достаточно умной — узкое место теперь не интеллект модели, а структура [[Agentic Workflow|воркфлоу]]. Каждый новый тред Codex пользователь начинает как «операционная система»: объясняет репо, стандарты, инструменты, известные сбои. Плагины упаковывают этот живой контекст в переиспользуемую инфраструктуру, чтобы агент перестал нуждаться в человеке как в ОС.

## Ключевые идеи

- **Codex (OpenAI)** достиг 82.7% на [[Terminal-Bench]] 2.0 (ранее 75.1%) — модель справляется с длинными многоинструментальными задачами без потери нити
- **Узкое место переместилось**: воркфлоу живёт в голове пользователя и перезагружается с каждым новым тредом — это и есть новая неэффективность
- **Более сильная модель в размытой среде** не увеличивает полезность — она ускоряет уверенные ошибки (reviews, missing the team standard; release notes drifting into engineering language)
- **[[Codex Plugin]]** = [[Skill File|навык]] + доступ к инструментам + живые интеграции + детерминированные проверки + зафиксированные failure modes команды
- После установки плагина агент перестаёт требовать, чтобы человек был операционной системой
- **Карьерный навык следующих двух лет**: не длина промпта, а понимание того, какие части работы должны стать переиспользуемой инфраструктурой — те, кто научится «упаковывать», будут накапливать преимущество

## Фреймворк: [[Decision Ladder]] (Лестница решений)

| Уровень | EN | Когда применять |
|---------|-----|----------------|
| Промпт | Prompt | Разовая задача, не повторяется |
| Навык | Skill | Повторяется, нет внешних зависимостей |

| Не делать ничего | Don't bother | Задача меняется быстрее, чем окупается упаковка |

## Что использовать для нашего портфеля

Как провайдер [[Implementation Layer]] и AI-интегратор:

- **Главный инсайт**: клиенты, купившие доступ к Codex / Claude Code без настроенного воркфлоу, получают именно «более быстрые и уверенные ошибки» — это точная формулировка боли, которую закрывает [[Implementation Layer]]
- **Позиционирование**: наша ценность — не модель, а структура вокруг модели; [[Moat]] строится на упакованных воркфлоу, а не на доступе к API
- **Конкретная услуга**: воркфлоу-аудит → [[Decision Ladder]] → [[Workflow Packaging]] → поддержка плагинов — это законченный engagement
- **PE-канал**: портфельные компании, переходящие на агентные инструменты, имеют незакрытый gap между мощью модели и реальной продуктивностью; [[Forward Deployed Engineer|FDE]]-модель входа работает здесь напрямую
- **Диагностический вопрос для клиента**: сколько раз в неделю команда объясняет контекст агенту с нуля? — прямой индикатор потребности в [[Workflow Packaging]]
- **Связь с [[Agentic Workflow]]**: [[Codex Plugin]] — это операционализированный [[Harness]]; язык плагинов Codex можно использовать как точку входа для разговора о нашей [[Implementation Layer]]-архитектуре
