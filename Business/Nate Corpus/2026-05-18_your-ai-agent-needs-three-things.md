# Три примитива автономного агента: память, инструменты, пульс

> "Memory. Proactivity. Tools."
> *Память. Проактивность. Инструменты.*

## Суть

Anthropic добавила в Claude Code команду `/loop` — cron-планировщик, позволяющий агенту просыпаться и выполнять задачи без участия пользователя. По версии автора это последний недостающий «кирпич»: в связке с [[Open Brain]] (память) и [[MCP]] (инструменты) получается стек, функционально эквивалентный [[OpenClaw Stack]] — но без сопутствующих рисков безопасности.

---

## Три примитива

| Примитив | EN | Реализация | Статус |
|---|---|---|---|
| Память | Memory | [[Open Brain]] — личная файловая/векторная память в Claude Code | Готово |
| Инструменты | Tools | [[MCP]] (Model Context Protocol) — внешние вызовы и данные | Готово |
| Пульс | [[Heartbeat]] | [[Loop Command]] (`/loop`) — cron-расписание внутри Claude Code | Новое |

### [[Loop Command]] — механика

`/loop` запускает агента по расписанию: каждые 5 минут, каждый час, каждое утро в 9:00 — без ручного промпта. До этого агент был реактивным. Теперь агент сам инициирует работу.

```
[[Open Brain]]  (память)
  + [[MCP]]       (инструменты)
  + [[Loop Command]] (пульс)
= автономный агент под вашим контролем
```

---

## [[OpenClaw Stack]] без хаоса

Архитектурная ставка автора: разделение планировщика и памяти (а не монолит) делает систему надёжной и аудируемой (→ [[Audit Trails]]). Claude Code как [[Harness]] обеспечивает изоляцию и контроль, которых нет у OpenClaw.

---

## Варианты использования

- **Мониторинг** — агент собирает данные по расписанию (энергопотребление, метрики)
- **Sales pipeline** — ежедневные обновления статусов без ручного ввода
- **Утренний брифинг** — агент работает ночью, утром готовит доклад по всем источникам
- **`/life-engine` skill** — пример интеграции: Claude Code + MCP + Telegram + `/loop`

## Что использовать для нашего портфеля

**Контекст**: AI-интегратор, [[Implementation Layer]], работа с [[Business Object]], PE как канал.

**1. Фоновые агенты как продукт** — три примитива доступны в Claude Code без кастомной инфраструктуры. Для PE-клиентов это конкретный [[Workflow Completion]] кейс: «агент заменяет утренний ручной обход трёх систем».

**2. Архитектурный аргумент** — разделение памяти и планировщика (не монолит) продаётся как надёжность и соответствие требованиям [[Audit Trails]]. Это часть [[Implementation Layer]] pitch.

**3. Порог входа** — Claude Code уже используют не только разработчики (маркетологи, PM). Для клиентов без инженерной команды это снижает барьер к [[Agentic Workflow]].

**4. Проверить** — поддерживается ли `/loop` в корпоративных развёртываниях Claude Code (не только desktop/CLI). Пост написан до широкой доступности.

**Открытый вопрос**: Какой [[Business Object]] выиграет первым от фонового агента в портфельной компании — финансовый мониторинг или обновление pipeline данных?
