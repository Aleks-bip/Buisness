# 4 типа агентов: как выбрать нужный

> "The word 'agent' has become the 'cloud' of 2026. Everyone uses it. Almost nobody means the same thing."
> *«Слово "агент" стало "облаком" 2026 года. Все его используют. Почти никто не имеет в виду одно и то же.»*

## Суть

Существуют **четыре архитектуры агентов**, которые используют один и тот же термин, но решают принципиально разные задачи. Ошибка в выборе архитектуры — это не просто техническая проблема, это потеря квартала. Рынок агентов: $8 млрд в 2025 → $50+ млрд к 2030 (MarketsandMarkets, BCC Research).

## Четыре архитектуры

| # | Тип (RU) | Тип (EN) | Суть | Принцип работы |
|---|----------|----------|------|----------------|
| 1 | [[Coding Harness\|Кодовый обвяз]] | Coding Harness | Агент внутри IDE, пишет/правит код в паре с разработчиком | [[Decomposition\|Декомпозиция]]: задача разбивается на тест → реализация |
| 2 | [[Dark Factory\|Тёмная фабрика]] | Dark Factory | Автономный производственный конвейер без участия человека в цикле | [[Specification-as-Code\|Спецификация как код]]: поведение определяется тестами и контрактами |
| 3 | [[Auto Research\|Авторесёрч]] | Auto Research | Замкнутый исследовательский цикл: сбор → синтез → вывод | [[Evals\|Метрика + барьер]]: метрика качества + guardrail |
| 4 | [[Orchestration Framework\|Оркестрационный фреймворк]] | Orchestration Framework | Координация нескольких агентов (CrewAI и подобные) | [[Handoff Contract\|Контракт передачи]]: явные интерфейсы между агентами |

## Ключевые ошибки (анти-паттерны)

- Использовать [[Dark Factory|тёмную фабрику]] для написания романа (творческая задача ≠ производственный конвейер)
- Тянуться к [[Orchestration Framework|оркестрационному фреймворку]] для задачи, которую решает один агент с хорошим тест-сьютом
- Направлять [[Auto Research|авторесёрч]] на написание нового ПО с нуля — *"like pointing a profiler at an empty file"* / *«как запускать профайлер на пустом файле»*

## Принципы управления (по архитектуре)

| Архитектура | Управляющий принцип | Что ломается без него |
|-------------|--------------------|-----------------------|
| [[Coding Harness]] | [[Decomposition]] | Агент не знает, где остановиться |
| [[Dark Factory]] | [[Specification-as-Code]] | Нет верифицируемого определения "готово" |
| [[Auto Research]] | Metric + Guardrail | Бесконечный цикл без критерия выхода |
| [[Orchestration Framework]] | [[Handoff Contract]] | Агенты теряют контекст на стыках |

## Что использовать для нашего портфеля

**Контекст**: AI-интегратор, [[Implementation Layer]], [[Implementation Fabric]], [[Business Object|бизнес-объекты]], PE как канал.

**Coding Harness** — инструмент разработки нашей команды, не продукт для клиента. Cursor/Claude Code для ускорения [[Harness|внутреннего харнесса]].

**Dark Factory** — наиболее релевантна для клиентских внедрений: автоматизация повторяющихся операционных процессов (обработка документов, [[Systems of Record|обновление систем записей]], [[Workflow Completion|завершение рабочих процессов]]). Ключевое требование: наличие [[Specification-as-Code|спецификации как кода]] — без этого фабрика не верифицируема.

**Auto Research** — применима в due diligence (PE-канал): автоматизация сбора и синтеза данных по портфельным компаниям. Требует чёткой метрики качества на выходе.

**Orchestration Framework** — актуальна при построении [[Implementation Fabric|имплементационной ткани]] для клиентов со сложными интеграциями. Риск: без [[Handoff Contract|контрактов передачи]] системы разваливаются на стыках агентов.
